# Implementation notes

Context for picking this up later. What the study does, how it is built, what is
settled, and what is still broken. Written after the session that added the eight
matched mazes, the questionnaire flow and the metrics.

---

## 1. What the study is

A first-person hedge maze in three.js. An LLM-generated assistant suggests which way
to go at junctions. The research question is what happens to reliance when the
assistant is taken away.

Three conditions, set by `?condition=` on the study url:

| condition | mazes 1–4 | mazes 5–8 |
|---|---|---|
| `no_ai` | no assistant | no assistant |
| `stable_ai` | assistant | assistant |
| `disappear` | assistant | **no assistant** |

`disappear` vs `no_ai` over the last four mazes is the comparison the design rests
on. Neither has an assistant there, so any difference is the after-effect of having
had one.

## 2. Participant flow

```
Welcome screen                      no maze, no controls, no counters
  -> Questionnaire 1                iframe over the stage
  -> Brief                          + an AI paragraph for the AI conditions only
  -> Practice run                   controls only, tagged "training" in the log
  -> Mazes 1-4
  -> Questionnaire 2                iframe, closing it returns to maze 5
  -> Mazes 5-8
  -> Questionnaire 3                takes the whole page; nothing to return to
```

All on one url. The maze showing is held in `sessionStorage`, never in the address,
so a participant cannot skip ahead. Advancing reloads the page, which is what keeps
each trial clean.

**Questionnaire links** live in one place: `SURVEY_LINKS` in `public/maze.js`, keyed
by condition then `start` / `mid` / `end`. An empty string still shows the step but
offers only Continue — that is the safe state for piloting, since nothing can post
into a real response set.

**Knowing a questionnaire is finished** is unsolvable from our side: the iframe is
another origin. Two routes are wired. Qualtrics can redirect its End of Survey to
`/survey-done.html`, which is our origin and posts a message up so the overlay closes
itself; otherwise the participant closes it with the button on the bar. The redirect
is an upgrade, not a requirement.

## 3. The mazes

Eight, in `public/mazes8/`, generated by `mazes8/scripts/build-set.mjs`.

Matched on: **53 moves** shortest path, **25 branch points**, **24 choice points**
(branch points where two or more branches independently reach the exit). Identical in
all eight — that is the point of the set.

Exits are spread across three zones, applied by `mazes8/scripts/set-exits.mjs`:

| zone | mazes |
|---|---|
| bottom | 1, 2, 3, 6 |
| bottom-right | 4, 7 |
| bottom-left | 5, 8 |

They all used to exit at the same square, which let a participant learn "head south"
and be roughly right without reading anything — a shortcut sitting exactly where the
disappear manipulation needs navigation to matter.

A **left-hand exit is not reachable at 53 moves in any maze**: the start sits top
centre, so the left wall is nearer and every left exit came out at 35–47. A fourth
zone was possible (right-hand exit on maze-7) but cost that maze a branch point, and
a matched set is worth more than one more direction.

### Grid encoding

`(2N+1)` thin-wall. Odd/odd are cells, even/odd and odd/even are the wall tracks
between them, even/even are corner posts. **Never open a corner post** — it merges
four cells into a 2×2 room instead of a corridor.

### Known cosmetic issue, deliberately left

195 one-cell hedge stubs and 27 orphaned corner posts across the set: the short walls
and free-standing cubes visible in first person. Investigated at length and left
alone by decision.

What was learned, so nobody repeats it:

- They cannot be avoided while carving. Of 5,400 sampled braided mazes **none** had a
  minimum hedge run of even 2 cells, and the count holds at 20–28 whatever the
  junction count.
- Greedy repair does not work: opening a stub orphans a post, re-attaching that post
  lays a fresh stub. 98.6% of mazes never settled; extend-only failed outright.
- **Hill-climbing does work** (`removeBlocks` in `mazes8/scripts/lib.mjs`) because it
  accepts moves that leave the score unchanged. Climbing on blocks alone wrecks
  everything else, so loops and pocket size are part of the score.
- A block-free candidate set exists in `mazes8/candidates/` if this is ever revisited.

## 4. How hints are made

**No AI runs during a trial.** The game downloads a static JSON file at trial start.

```
build-solutions.mjs   AI returns whole-maze routes, each verified walkable
                      -> public/mazes8/solutions/maze-N.json
derive-hints.mjs      NO AI. Arithmetic over those routes
                      -> public/mazes8/hints/maze-N.json
runtime               one fetch, CUE_SOURCE="file"
```

A junction distance is `1 step onto the branch + that branch's remaining distance
along the best verified route through it`. Because every number is a sum over
segments already checked to be walkable, the model cannot invent a distance.

### The accuracy problem, measured

A branch that no verified route walks gets **no claim at all**. So the cue names the
best branch *it knows about*, which may not be the best branch. Measured on the
previous hint set: 30 junctions out of 106 where the cue pointed away from the truly
shortest branch, 295 branches silent, 73% of distances exact, **zero understated**.

Errors are always conservative — the cue never claims a branch is closer than it is —
and the ranking is only wrong when a better branch was never covered.

More AI routes help but do not fix it: routes run start→goal, so a branch into a dead
end can never be covered by this method, whatever the model.

The open decision is whether that error is acceptable as "the assistant is fallible"
or should be replaced by **deliberate, logged error** — a policy file naming which
junctions mislead and by how much. Deliberate error is more defensible in a write-up
than unquantified LLM error.

## 5. Metrics

Every run has an id: `?pid=...`, or minted per tab. Written into every log row.

Recorded per maze on finishing (`action: "maze_summary"`):

```
completion_ms, completion_ms_including_help, help_paused_ms
moves_taken, shortest_possible, excess_moves
revisited_cell_moves, back_button_moves
junctions_passed, junctions_with_a_cue, followed_cue, median_decision_ms
```

Per junction (`action: "junction_decision"`): time stood there before moving, which
branch was taken, which the assistant named, whether they match. `followed` is `null`
where no cue was shown — `no_ai` throughout, `disappear` after maze 4 — which is
distinguishable from "shown a cue and ignored it".

**Excess is measured against the shortest route.** With several correct paths any
other benchmark is arbitrary. Wrong turns are deliberately not counted for the same
reason.

**Decision times are raw**, with no reading-time subtraction: the comparison that
matters is over the last four mazes where neither group has an assistant.

**Time on the controls card is held out of the clock**, since that card explains the
buttons, not the maze. Both totals are kept so a time including help is recoverable.

**Practice rows are tagged** `maze: "training"`, `maze_index: -1`, `phase: "training"`.
Without this they carried `m8-1` and index 0 and were indistinguishable from the first
real trial.

### Storage

Three places, deliberately:

- `localStorage` per participant — a cache, not a record. It leaves with the browser.
- **the server** — batched every 1.5s, appended to one file/list per participant.
  A failed send stays queued; `pagehide` fires a `sendBeacon` so a closing tab does
  not take the last rows with it.
- **export** — Save CSV gives one tidy row per maze, shift-click gives every event,
  Save JSON gives the raw log.

Locally that is `error_logs/runs/<pid>.jsonl`. On Vercel the filesystem is ephemeral,
so `api/run-log.js` writes to a Redis-compatible KV via `KV_REST_API_URL` and
`KV_REST_API_TOKEN`. **Check `/api/run-log?health=1`** — it writes a key and reads it
back, because "configured" and "working" are not the same thing.

## 6. Spend guardrails

Generation is the only thing that costs money and it runs unattended.

```
MAX_LLM_CALLS    requests a process may make      default 40
MAX_LLM_TOKENS   input+output it may spend        default 400000
```

Checked **before** a request is sent. Every run appends its token count to
`error_logs/llm-spend.jsonl`.

## 7. Traps already fallen into

Listed because each one cost real time and each looks like something else.

**Two functions with the same name.** Adding `isOpenCell(x, y, maze)` silently
replaced the existing `isOpenCell(cell, maze)` — later declaration wins — and broke
all eighteen callers. Symptom: every route rejected with "cell 9,1 is a wall", the
start cell, which is plainly open. Looked exactly like the model failing.

**429 retried instantly.** The attempt loop spent all three attempts in under half a
second on a rate limit and wrote six mazes empty while the API was healthy. Now backs
off 20s then 40s.

**`Number(x) || default` on a limit of 0.** Turned "make no calls" into forty.

**Temporal dead zone, three times.** `TRAINING_STEPS`, `startSurveyOpen`,
`NEEDS_INTRO` were each declared below code that runs during module init. Symptom:
a panel silently never appears.

**CSS source order.** `.hidden` sat above `.task-complete-link`; same specificity, so
`display:inline-flex` won and the questionnaire link showed on every maze. `.hidden`
is now last in the file with `!important`.

**`sessionStorage` is per tab.** The moderator view could never see the participant's
progress, so it drew the live position on the wrong maze. Progress is now mirrored to
`localStorage` for the moderator to read; the participant still owns the session copy.

**Stopping a batch does not stop the call in flight.** `TaskStop` killed the parent
shell and the child kept running and wrote its empty result.

**Escaping `\n` through a Python heredoc into JS.** Repeatedly produced literal
newlines inside string literals and regexes. Use `chr(92) + "n"`.

## 8. Where it stands

Working and deployed: the whole flow, the metrics, the questionnaires, the eight
mazes with spread exits.

**Broken locally, do not push:** hints. The exits moved, so every stored route ends
at the old exit and had to be regenerated. Mazes 1 and 2 are done (8 and 4 routes,
23/25 and 20/25 coverage). **Mazes 3–8 are empty** — each attempt hits the 180s
timeout on the raw-grid prompt.

Vercel is still on the previous mazes with their matching hints, which is at least
self-consistent. Keep it that way until the audit passes.

### The fix that is measured but not wired

Send the **contracted graph** instead of the raw grid: collapse the maze to its ~35
junctions and ~43 corridors before asking. Measured against the same model:

| | raw grid | contracted graph |
|---|---|---|
| per call | 60–180s, often timing out | **1.2s** |
| tokens | ~4,000 | ~1,200 |
| maze-6 | struggling | 6 routes, **found the optimal 53** |

The output becomes a node sequence, which expands back to cells deterministically —
so a route naming real edges *is* walkable by construction, and the only error it can
express is naming an edge that does not exist.

Also worth knowing: **`gemini-3.5-flash-lite` cannot do this task.** The 180s
timeouts, the truncations and the 32k reasoning budgets were all it struggling with a
search it cannot do. `gemini-3.5-flash` on a contracted graph answers in seconds.

Working code for the contraction and the accumulate loop exists in the session
scratchpad; it needs porting into `buildSolutionsPayload` and `findMazeSolutions`.

## 9. Commands

```bash
npm start                                    # http://localhost:3000
/study/participant?condition=disappear       # a run
/study/moderator                             # live view, follows the participant
/m8                                          # index of the eight

node mazes8/scripts/verify.mjs               # the set against the brief
node mazes8/scripts/audit-hints.mjs          # hints against BFS ground truth
node mazes8/scripts/preview.mjs              # contact sheet
node mazes8/scripts/set-exits.mjs --dry      # exit placement

LLM_PROVIDER=gemini GEMINI_MODEL=gemini-3.5-flash MAX_LLM_CALLS=3 \
  node mazes8/scripts/build-solutions.mjs maze-1 6 --set=mazes8
bash mazes8/scripts/derive-all.sh            # hints from routes, no AI
```

`?restart=1` clears the run and the practice flag. `?pid=P01` sets the participant id.
